## Sprint planning approach

The supplied Trello export contains 13 sprint lists and 85 task cards. The table below retains the list names and summarises each list's goal. The assessment assumption is that non-legal work is complete; three legal/compliance cards in Sprint 2 remain outstanding. The export does not provide dependable dated sprint records, velocity, or evidence of task completion, so no sprint dates or historical progress are invented here.

## Example sprint breakdown: Project Management

**Sprint goal:** Make client project intake and delivery visible to the client and the team.

**Selected tasks from the board**
- Submit New Project
- Upload Project Assets
- Track Project Status
- Assign Editors
- Manage Internal Tasks
- Manage Deadlines

**Proposed acceptance checks**
- A project can be submitted with the information needed to begin work.
- Project assets can be associated with the correct project.
- The current status, assigned editor, internal work, and deadline are visible to authorised users.
- The team can identify what needs attention and what is ready for review or delivery.

## Example sprint breakdown: Launch

**Sprint goal:** Check readiness and prepare for a controlled public launch.

**Selected tasks from the board**
- Conduct Beta Testing
- Prepare for Public Launch
- Set Up Monitoring
- Create Documentation
- Execute Public Launch

**Proposed acceptance checks**
- Beta testing findings are reviewed and important issues have a disposition.
- Launch preparation tasks are checked before the public launch.
- Monitoring is configured to help identify operational problems.
- Documentation is available for the people operating the service.
- Legal and compliance tasks remain visibly outstanding and are not represented as completed.

## Reflection

The sprint lists divide a broad project into manageable themes. The sequence connects the business foundation to branding and website work, then account access, client delivery, editing, communication, billing, marketing, administration, and launch. This makes it easier to discuss dependencies and identify what a sprint is intended to achieve. A stronger real-world sprint record would also include dates, selected versus unselected work, owners, estimates, blockers, review results, and retrospective actions. The supplied CSV alone cannot establish those historical details.
